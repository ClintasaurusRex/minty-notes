### Review fixes (0.1.1)
1. **Handover refused when work cannot be saved.** The editor freezes edits and saves before releasing; if saving fails it replies "refused", keeps the lock, and keeps editing with its changes intact. A thrown save error counts as a refusal. The requester only steals from a window that never acknowledges (frozen).
2. **Ownership enforced everywhere.** A stolen lock (or a commit refused by storage) makes the window read-only, cancels queued saves and retries, and stops backups. Storage now checks an owner token on every commit and restore, so stale retries from an old window are refused. Unsaved changes are held in memory with a banner: "Edit here and save them" (saved on top of the latest data) or "Discard them".
3. **Trashed pages of deleted sections.** Deleting a section/notebook moves its trashed pages' location to the Inbox. IndexedDB migration 1 → 2 repairs existing data; version-1 backups containing the orphan now restore (the page goes to the Inbox, with a warning). Live orphans are still rejected.
4. **Backups track revisions, not timestamps.** Each commit increments a stored revision in the same transaction; each snapshot records the revision it captured, read with the archived data. The interval uses a monotonic clock within a session; a clock set backwards counts as due.
5. Also found and fixed while testing: after taking editing back, the page could briefly reload without the edit that was mid-save (held edits are now saved before reloading, and in-flight saves are overlaid).

### Held-edit recovery fix (0.1.2)
The recheck of `0f28457` found that taking editing back replayed held changes as whole stale records (a body edit also carries its page record), which could revert a newer title or resurrect a trashed page's old live location in a deleted section (and then fail backup validation). Now:
- Held changes keep the stored version they were based on, and are **merged field by field** with the latest stored data. Only fields this window actually changed are applied; newer titles, locations, Trash state, and unrelated content are preserved.
- Conflicts (same field changed in both windows), edits to records deleted elsewhere, blocked deletions, and moves into deleted sections are **not applied in place**: they go to a new **"Recovered changes" page in the Inbox**, and a message says how many.
- Regression tests (`src/store/heldRecovery.test.ts`, 7, fully awaited — no timers): the two reported cases (rename in B; trash + delete notebook in B), same-text conflict, edit to a page deleted forever, conflicting rename, non-conflicting rename alongside B's new content, move into a deleted section. Each ends with a complete backup that passes validation and restores into a clean workspace with the expected result. The browser frozen-window test now also renames the page in B and checks A keeps B's title.

### Stage 2 data-safety review (0.2.1)
A focused review of shared references, project copies, archive/Trash/deletion, upgrade and backup compatibility, and two-window editing found four concrete defects. Each was reproduced first (isolated fake-indexeddb workspaces and, for the date field, real Chromium), fixed, and covered by a test that fails without the fix:
1. **A mistyped due-date year made every later backup unrestorable.** Chrome's date field produced `20261-12-15` for a five-digit year; the store accepted it and restore validation then refused the whole backup (“Project #1 is invalid”). Years 0001–0099 (Chrome gives `0099-12-15` for a two-digit year) were also wrongly treated as invalid because `Date.UTC` maps them to 1900–1999. Fixed: correct date-only check for all four-digit years; the store ignores invalid due dates (the previous date stays); the field has `max="9999-12-31"`, which caps the year at four digits in Chrome; and a backup that already contains an invalid due date (possible from 0.2.0) restores with that date cleared and a warning.
2. **A refused held project deletion still moved the project's notes to the Trash.** If window A deleted a project forever while it could not save, and window B then changed that project, taking editing back kept the project (correct) but applied A's “move notes to Trash” part, leaving a live project without its notes.
3. **A refused held category or tag deletion still removed it from every record.** If B renamed the category/tag meanwhile, it was kept but stripped from all notebooks, sections, pages, and projects.
4. **A refused held page deletion still emptied the page and cut its links.** If B renamed the page meanwhile, it was kept but its text boxes and images were deleted, its pins/hides in other projects were removed, and its project copies lost their source link. (The emptied-page part existed since Stage 1.)

Fix for 2–4: `withoutRefusedCascades` in `src/store/reconcile.ts` predicts which held deletions will be refused (with the same rules as before) and drops only the side effects that belonged to them, before anything is merged. Deletions that are not refused behave as before.

Checked and found sound (no change needed): shared-reference edits reaching every linked project; copy independence both ways; project deletion never touching library pages; deleting an original keeping its copy's text and image bytes (assertion added, through a full backup → clean restore); archive/Trash/restore record validity; Stage 1 database and backup upgrades; failed migration and invalid restore preserving the workspace; read-only windows refusing every Stage 2 change (test added); merges of unrelated changes and removal of dangling links.

- **Keyboard moves without dragging:** Alt+←/→ (column) and Alt+↑/↓ (order) on a focused card, plus visible move buttons; focus follows the card and a live region announces the new position. Drag-and-drop works too.
- **Field-service / software workflow:** Overview shows “Next tasks” (Doing first, then due date and priority) and a files summary; Home shows overdue and next-7-day tasks and each project's next task; “New linked note” makes a project note for a task in one click.
- **Combined Tasks view:** open tasks across projects with project name, status, priority, and due date; filters for status, minimum priority, due range, project, and archived projects; sort by due date, priority, project, or recent change; clicking a task opens it on its project's board. Archived projects' tasks are hidden unless included; trashed projects' tasks are hidden everywhere until restored.
- **Task-to-note links:** link any existing note (by ID — never copied). Links follow moved notes, show “in the Trash” for trashed notes (and return when restored), and are removed everywhere when a note is deleted forever (the confirmation says how many tasks lose the link). Notes show “Linked from tasks”.
- **Files tab:** saved local paths (copy button; the UI explains browsers cannot open local folders) and http/https web links such as Dropbox links (open in a new tab), each with a description. Unsafe schemes are never turned into links. No Dropbox API, sync, or backend.
- **Templates:** “Save as template” on a page or a project; “New from template” on Home and in a project's notes; manage (rename, describe, delete) in Settings. Every use creates independent records with new IDs; template-internal task→note links are remapped to the new notes; library links stay shared; job details are not copied. Templates outlive their source pages, and deleting a template keeps what was made from it.
- **Search** also finds tasks by title and details.
- **Storage:** new `tasks` and `templates` stores; everything goes through the same change sets, one-transaction autosave, owner-token fencing, revision counter, full backup/restore with validation, and held-edit reconciliation. **Migrations:** IndexedDB 3 → 4 (and 1/2 → 4) and backup format 2 → 3 (and 1 → 2 → 3).
- **Deletion rules:** deleting a project forever deletes its tasks (named in the confirmation) and, as before, moves its notes to the page Trash; deleting a page forever, a category, or a tag removes it from tasks and templates. No ID ever points at a missing record.

### Stage 4 slices 1–3 — richer notes, annotations, and document import (0.4.0)
Built in three checked slices (each committed and pushed separately) on data format 4 / IndexedDB 5 (no record rewrites; see `DATA_FORMAT.md`). Baseline before any change: `npm ci`, `npm run check` (115 unit tests), and `npm run test:e2e` (22 browser tests) all passed at `8f91dfd`.
- **Slice 1 — tables, code, internal page links (done):** editable tables in text boxes (toolbar insert; Tab/Shift+Tab between cells, Tab in the last cell adds a row; floating row/column controls: add above/below/left/right, delete row/column, header row, merge/split, delete table); code blocks (toolbar or Ctrl+Alt+C; three Enters leave) and inline code (Ctrl+E or backticks); internal page links (`[[`, Ctrl+Shift+K, or the toolbar; on selected words or inserting the page title). Ctrl/Cmd+click or Alt+Enter follows a link (a plain click in a read-only window); “← Back to …” returns. Links are by page ID: moved/renamed pages keep working; a page in the Trash shows “in Trash” and following it offers Restore; a page deleted forever leaves the link text marked “deleted” (backups still restore, with a warning). Pages show “Linked from notes”; Trash and Delete-forever messages count linking notes. Alt+F10 jumps to the toolbar, Esc returns. Pasted HTML tables keep bounded spans (≤ 50) and no column widths.
- **Slice 2 — image markup and sketches (done):** select an image → “Mark up” (or Enter / double-click) opens a full-window editor: arrow, line, rectangle, ellipse, text label, pen, highlighter, blur, redaction box, crop; select/move/resize with handles; colours and three sizes; undo/redo inside the editor; Done saves it as one page undo step. Keyboard: tool letters (V A L R E T P H B X C), Enter adds an annotation in the middle (or edits a label), Tab steps through annotations, arrows move (Shift ×10), Alt+arrows resize, Delete removes, Ctrl+D duplicates, Esc deselects then closes; a live region announces changes. **Sketch** (toolbar) adds a vector drawing object with the same tools (no blur/redact/crop); an empty new sketch is discarded. Markup is stored on the image object (`markup`, natural-pixel coordinates; crop is non-destructive) and the attachment bytes never change. **Blur is visual only; a redaction box only covers the area on screen — the original pixels stay in the workspace and its backups.** “Save PNG copy” downloads a flattened PNG in which redacted pixels are replaced with solid black (checked pixel-by-pixel in Chromium) and blurred areas are pixelated. Label text is searchable. Held-edit merge: a markup changed in both windows keeps the other window's version and puts this window's marked-up copy on the “Recovered changes” page.
- **Slice 3 — local DOCX and text-PDF import (done):** “Import document” in the Inbox, standalone notes, each notebook section, and each project (navigator and project notes card). The original file is stored unchanged as an attachment (also in backups, as `.docx`/`.pdf`) and the new page is an **editable draft** with an “Imported draft” banner: source, size, date, **Preview original**, **Download original**, and **Conversion notes** saying exactly what was not converted. DOCX (mammoth, in a Web Worker): headings, bold/italic/underline/strike, lists, tables (spans bounded), links (http/https/mailto only), and PNG/JPEG/GIF/BMP/WebP pictures as image objects; long documents become several stacked text sections; EMF/WMF pictures, macros, and layout are reported. Text-based PDF (PDF.js): text per page rebuilt into paragraphs, headings by size, bullet lists, hyphen joins; pages without text (scanned), pictures, forms/annotations, scripts (never run), attachments, and >300 pages are reported; no OCR. Preview: PDF pages drawn locally with PDF.js; DOCX shown as a read-only conversion rebuilt from the stored file. Refused with a reason and nothing stored: empty, >50 MB, not DOCX/PDF, legacy `.doc`, RTF, ZIPs without `word/document.xml`, ZIP bombs (declared size > 300 MB or > 5,000 parts). A real DOCX/PDF that cannot be converted (damaged, password-protected, scanned) is kept as the original only if the user agrees. Converters load only when used and are in the offline cache (PDF import tested offline).

- **Found and fixed while testing (Stage 4):** (1) clicking into a table or link made contextual tools appear, the toolbar wrapped, and the page shifted under the pointer, turning a click into a drag selection — contextual tools now float over the page and the arrange controls are always laid out; (2) Ctrl+Z inside the markup editor also reached page undo (and removed the screenshot) — page shortcuts, paste, and Alt+N now ignore events while any dialog is open; (3) a page link could be inserted instead of applied to selected words when the picker closed (focus restoration) or when the shortcut followed a keyboard selection too quickly — the picker closes before the selection is restored and the shortcut reads the live selection (verified with 15 repeated runs).

## Known limitations
- Stage 1 limitations still apply: held changes live only in that window's memory; no character-level text merge; opening a page can save re-measured text heights; undo is per page and in memory; no multi-select, guides, snapping, alt-text editor, tables, checklists, shapes/annotation, document import, or PDF export; image bytes of deleted objects are kept; backups are built in memory; basic phone layout; folder backups need Chrome/Edge on a desktop and only run while the app is open; restore replaces the whole workspace.
- Project details, categories, tags, pins/hides, archive, and project trash are not in undo history (page Trash and project Trash cover deletion).
- Tags are on pages only (not on projects); categories are on projects, notebooks, sections, and pages.
- Search reads all stored text into memory and is rebuilt after each save; it has not been measured on the 1,000-page synthetic dataset (Stage 5). Original attachment contents are not searched — only their file names.
- Recently opened pages are per device (`localStorage`) and not in backups.
- Local file paths are copied, not opened (browsers cannot open arbitrary local paths). Dropbox links open in a new tab and need a connection.
- A project copy shares image bytes with the original (bytes never change, so the pages stay independent).
- Deleting a page forever also removes it from other projects' pins; there is no per-link history.
- An invalid due date already stored by 0.2.0 stays in this browser's workspace until the date is changed; restores clear it (with a warning).
- Two windows can each create a category or tag with the same name while one cannot save; both are kept (rename or delete one in Settings).
- In a held-edit merge, a pin in one window and a hide of the same page in the other both survive; the page then shows as pinned.
- **Stage 3:** task changes (moves, edits, deletes) are not in undo history; task deletion asks for confirmation and is permanent (no task Trash). Deleting a project forever deletes its tasks. Tasks have no recurring dates, reminders, notifications, time tracking, assignees, or calendar sync. Drag-and-drop is basic (drop on a card inserts before it; drop on a column appends) and was not browser-automated. Templates are snapshots: editing a template's content means saving a new one (rename/describe/delete only in Settings). A project template keeps file locations, equipment, and software but not customer, site, job number, contacts, dates, or task status. Template images reuse attachment bytes (never changed), like project copies. Task filters are per device (`localStorage`). Local paths are copied, never opened. Daily work logs are not built (optional later). Portable project export is Stage 4.
- **Stage 4:** Tables have no drag-to-resize columns (they size to the text box) and no cell colours; code blocks have no syntax highlighting or language label. Page links: a link to a page deleted forever stays (marked “deleted”) rather than being removed; links inside a project template still point at the original pages (not remapped to the new project's notes); backlinks are read when a page opens (not live); no page-title autocomplete inside the text beyond the picker. Markup: one editor at a time in a modal window; no multi-select, rotation, or snapping; text labels have no font choice; blur and redact areas always draw under other annotations; **the original image (and every backup) keeps redacted pixels — only “Save PNG copy” removes them**; flattened blur is a pixelation, not a guarantee; markup on SVG images uses the image's own size. Sketches scale with their box (the drawing does not extend). Import: no OCR or handwriting recognition; legacy `.doc`, RTF, ODT, Markdown, and plain-text import are not supported; DOCX page layout (page size, columns, headers/footers, text boxes, fonts, comments, tracked changes, footnotes) is not reproduced, and pictures inside a paragraph are placed after it; PDF tables, columns, and reading order are not reconstructed and PDF pictures are not extracted; text of CJK PDFs may need character maps that are not bundled; the DOCX preview is a fresh conversion, not Word's layout; ZIP-bomb protection uses the sizes the ZIP declares (plus the 50 MB file limit and the worker); imports go to the Inbox, standalone notes, a section, or a project (not drag-and-drop onto a page).
- JavaScript bundle is ~1.08 MB (≈ 340 KB gzip) for the main app, cached after the first visit; mammoth (~310 KB) and PDF.js (~430 KB + 1.26 MB worker) load only when importing or previewing and are cached for offline use.
